# Fleet Ops Console

Fleet Ops Console for Northbound Logistics Ltd. This repo currently covers the **data layer**: 400 generated vehicles, a documented data schema, and a state store with persisted filters and selection.

Built with Vite, React, Zustand and Vitest.

## Getting started

```bash
npm install
npm run dev        # start the app
npm test           # run unit tests
npm run lint       # run ESLint
npm run generate   # regenerate src/data/vehicles.json
```

## Vehicle data

400 vehicles are generated by a Node script and committed as a static file: `src/data/vehicles.json`.

```bash
npm run generate
```

The generator (`scripts/vehicleGenerator.js`) uses a seeded random number generator and a fixed base timestamp, so running it twice always gives the same file. A test checks that the committed JSON matches the generator output.

### Schema

The schema is documented in [`vehicle.schema.json`](./vehicle.schema.json) (JSON Schema, draft 2020-12).

| Field        | Type   | Description                                              |
| ------------ | ------ | -------------------------------------------------------- |
| `id`         | string | Unique id, `V-001` to `V-400`                            |
| `name`       | string | Display name, for example `Van NB-017`                   |
| `status`     | string | One of `active`, `idle`, `maintenance`, `offline`        |
| `lat`        | number | Latitude, 5 decimals, inside the operating area          |
| `lng`        | number | Longitude, 5 decimals, inside the operating area         |
| `lastUpdate` | string | ISO 8601 timestamp (UTC), within 24 hours of the base time |

## State store

The store is in `src/store/useFleetStore.js` (Zustand).

```js
{
  byId: { 'V-001': { ...vehicle }, ... },  // all vehicles, looked up by id
  ids: ['V-001', 'V-002', ...],            // fixed display order
  filters: { search: '', statuses: [] },   // default filters
  selectedIds: []                          // empty selection
}
```

Actions: `setFilters`, `resetFilters`, `toggleSelected`, `clearSelection`, `updateVehicle`.

### Why this shape

- **Flat `byId` + `ids`:** `updateVehicle` creates a new object only for the changed vehicle. The other 399 keep the same reference, so memoized rows do not re-render when one vehicle updates.
- **Separate slices:** `filters` and `selectedIds` are independent from vehicle data, so changing a filter or selection never touches the vehicle objects.
- **Persistence:** only `filters` and `selectedIds` are saved to `localStorage` (key `fleet-ops-state`). Vehicle data always comes from the data file or live updates.

```bash
npm test
```

10 tests: 400 valid records with no duplicate ids, generator is deterministic, store initial state, selection, filters, and single-vehicle updates.
